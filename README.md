# wg-awg-relay

Проект релея WireGuard / AmneziaWG с поддержкой произвольного количества IPv4- и IPv6-подсетей за одним исходящим пиром.

## Архитектура

Разработка ведётся поэтапно:

1. **Библиотека протокола и маршрутизации** — независимые структуры конфигурации WireGuard/AmneziaWG, проверка входных данных, нормализация CIDR, таблица маршрутов IPv4/IPv6, longest-prefix match, детерминированное разрешение конфликтов и потокобезопасное динамическое обновление.
2. **Движок релея** — интеграция библиотеки с сетевым стеком и WireGuard/AmneziaWG-интерфейсом, управление маршрутами без пересоздания туннеля, сохранение состояния NAT.
3. **Программа и CLI** — загрузка конфигурации, команды управления и диагностика.
4. **Тестирование и документация** — unit-, property-based- и интеграционные тесты, включая проверку обновления маршрутов при активных соединениях.

## Принципы

- IPv4 и IPv6 поддерживаются в единой модели.
- Маршруты могут задаваться как внутри `peers[].routes`, так и общим списком `routes`.
- Сначала выбирается наиболее длинный префикс (LPM). Приоритет сравнивается **только между маршрутами с одинаковым префиксом**.
- Обновление таблицы маршрутов не должно требовать пересоздания туннеля.
- Изменение маршрутов не должно сбрасывать уже установленные NAT-сопоставления.
- Библиотека не привязана к CLI и может использоваться отдельно.

## Статус

Ведётся реализация первого этапа — библиотеки протокола и маршрутизации. До завершения интеграции с сетевым движком поддержка реального обмена WireGuard/AmneziaWG-пакетами не заявляется.

## Библиотека протокола

Пакет `protocol` пока не зависит от Linux, сетевых интерфейсов или CLI:

- `ParseConfig` / `Config.Validate` — разбор и проверка JSON-конфигурации;
- `Config.Routes` — сведение маршрутов из `peers[].routes` и общего `routes` к единому типу;
- `Config.EffectiveRoutes` — объединение маршрутов с `AllowedIPs` и разрешение конфликтов одинаковых префиксов по приоритету;
- `Config.PeerAllowedIPs` — полный эффективный набор сетей конкретного пира для безопасного обновления через UAPI;
- `RouteTable.Add`, `Remove`, `Replace` — динамическое изменение таблицы;
- `RouteTable.Lookup` — выбор пира для IPv4- или IPv6-адреса по LPM;
- `RouteTable.Snapshot` — стабильный снимок таблицы для диагностики и синхронизации.

У общего маршрута поле `peer` можно не указывать, если в конфигурации ровно один пир. При нескольких пирах поле `peer` обязательно. Пример находится в [examples/config.json](examples/config.json).

Запуск тестов:

```sh
go test -race ./...
go vet ./...
```

### Границы текущего этапа

На этом этапе реализованы модель конфигурации и алгоритм маршрутизации. Поля AmneziaWG сохраняются в конфигурации, но обработка обфускации и обмен зашифрованными пакетами ещё не реализованы. Для этого будет добавлен отдельный транспортный адаптер и движок релея.

### Кодек UAPI AmneziaWG

Пакет `protocol` также умеет формировать запросы для UAPI:

- `BuildUAPIConfig` — полная конфигурация устройства, включая AWG-параметры и объединённые AllowedIPs;
- `BuildPeerUAPI` — изменение одного пира с полной заменой только его списка AllowedIPs;
- `BuildPeerRemovalUAPI` — удаление одного пира;
- `ApplyUAPI` — отправка запроса по уже открытому соединению с обработкой ошибок устройства и отмены контекста;
- `UAPIClient` — подключение к Unix-сокету устройства, применение настроек и чтение текущего состояния через `get=1`.

Ключи принимаются в Base64 или hex и переводятся в hex-представление UAPI. Адреса интерфейса и MTU намеренно остаются ответственностью отдельного платформенного адаптера: UAPI WireGuard/AmneziaWG ими не управляет.

Поддерживаются также дополнительные параметры AmneziaWG 3.1: Header Protection, Content Padding, тайминги повторного handshake, случайные трейлеры и отключение cookie-пакетов. Для Header Protection ключ должен быть 32-байтовым, а значения `S1-S4` — не меньше 12 байт. Диапазоны параметров проверяются до отправки в UAPI.

## Движок синхронизации маршрутов

Пакет `engine` добавляет `RouteController`, который связывает конфигурацию, таблицу LPM и работающий UAPI-интерфейс:

- `ApplyInitial` применяет полную конфигурацию при первом запуске;
- `AddRoute` и `RemoveRoute` изменяют маршруты без команды `replace_peers`;
- изменения отправляются точечно для затронутых пиров;
- при передаче одинакового префикса другому пиру новый владелец обновляется раньше прежнего;
- при ошибке UAPI выполняется попытка восстановить прежние AllowedIPs, а локальная таблица не публикует новое состояние до успешного применения.

Контроллер пока управляет только конфигурацией WireGuard/AmneziaWG и маршрутизацией внутри устройства. Сетевые маршруты ОС, NAT/conntrack, forwarding и запуск процесса AmneziaWG будут добавлены следующими компонентами программы.

## Платформенный слой Linux

Пакет `platform/linux` управляет маршрутами через `iproute2`:

- отдельные команды `ip -4` и `ip -6`;
- `Apply` сначала устанавливает новые маршруты и только потом удаляет устаревшие;
- при ошибке выполняется попытка отката;
- изменения не перезапускают туннель и не очищают conntrack/NAT-состояние.

На этом этапе реализовано управление маршрутами ОС. Настройка forwarding, NAT и запуск процесса AmneziaWG ещё впереди.

Для NAT используется отдельная таблица nftables `inet wg_awg_relay` и правило masquerade на выходном интерфейсе. Настройка идемпотентна: повторный запуск не добавляет дубликаты и не выполняет `conntrack -F`. Forwarding IPv4 включается всегда, IPv6 — по явному параметру. Правила фильтрации FORWARD остаются ответственностью администратора/следующего слоя интеграции, чтобы не менять существующую политику firewall без явного решения.

Для userspace-режима `platform/linux.DeviceProcess` запускает `amneziawg-go -f <interface>`, ждёт готовности UAPI-сокета `/var/run/amneziawg/<interface>.sock` и останавливает процесс через штатный сигнал. Бинарный файл AmneziaWG устанавливается отдельно; проект не встраивает и не форкает криптографический движок.

`platform/linux.LinkManager` настраивает адреса интерфейса, MTU и поднимает TUN через `ip link` / `ip address`. Перед выполнением команд он проверяет весь набор адресов, чтобы не оставить интерфейс частично сконфигурированным из-за синтаксической ошибки в последнем адресе.
